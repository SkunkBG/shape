# Сервер мониторинга Shape

<p align="center">
  <b>Русский</b> · <a href="README.en.md">English</a>
</p>

Одна VPS, четыре контейнера, парк из десятков нод на одном экране.

```
нода в России ─┐
нода в Европе ─┼─→  https://push.<домен>  ─→  VictoriaMetrics
нода за NAT   ─┘         (токен)                    │
                                                    ↓
    вы ─→  https://grafana.<домен>  ─→  Authelia  ─→  Grafana
                                       (гейт)      (свой вход)
```

## Главное правило

**Дашборд только читает.** Ни одно правило ни на одной ноде не смотрит в
центральный источник и не может от него зависеть. Упал сервер мониторинга,
кончился домен, сгорела VPS — на нодах не изменилось ничего, ограничения
работают как работали.

Это не обещание, а свойство устройства: в Shape нет ни одной строчки, которая
читала бы решение извне. Важно не сломать это потом.

## Почему ноды отправляют сами

Не «сервер приходит за метриками», а наоборот. Причин три, и каждой хватило бы
одной:

- **WireGuard блокируют** — в России по отпечатку рукопожатия. Приватная сеть
  между нодами и сервером просто не поднимется.
- **NAT.** До части нод снаружи не достучаться в принципе.
- **Входящий порт на 28 нодах** — это 28 мест, где можно ошибиться.

Исходящий HTTPS на обычный домен с настоящим сертификатом неотличим от того,
что человек открыл сайт. Ноды при этом не открывают ничего.

## Что нужно до установки

- VPS: **2 ядра, 4 ГБ.** По данным хватило бы и 1/2 — 28 нод дают около
  семисот рядов, для VictoriaMetrics это ничто. Дело в Grafana: она в покое
  занимает 200–250 МБ и оживает при открытии дашборда на все ноды. На 2 ГБ
  влезет, но впритык и на одном ядре будет подтормаживать.
- Docker и `docker compose` v2.
- Домен и **три имени, уже указывающие на этот сервер**:

  ```
  grafana.<домен>   графики
  auth.<домен>      страница входа
  push.<домен>      приём метрик от нод
  ```

  Записи должны существовать **до** первого запуска: Caddy выпускает
  сертификаты сразу, а Let's Encrypt ограничивает число неудачных попыток.

## Установка

```bash
git clone https://github.com/SkunkBG/shape.git
cd shape/monitor
sudo bash install.sh
```

Спросит **три вещи** — домен, почту и пароль для гейта — и дальше сделает всё
сам: посчитает хеш пароля, напишет файлы, сгенерирует секреты в `.env` с
правами 600, проверит конфигурацию Authelia и поднимет стек.

Пароль можно не придумывать: пустой ввод — установщик сгенерирует свой и
покажет один раз.

В конце он напечатает оба пароля и готовую команду для нод. Больше ничего
делать не надо: открывайте `https://grafana.<домен>`.

## Доступ: два слоя, и это не паранойя

У Grafana опознаваемая страница входа. По ней определяется версия, по версии —
известные дыры. Гейт впереди отдаёт неаутентифицированному одно и то же, и
**снаружи невозможно понять, что за ним стоит**.

| Слой | Что это | Зачем |
| --- | --- | --- |
| Authelia | пароль гейта | чужие не видят даже, что здесь Grafana |
| Grafana | свой вход | тот, кто как-то оказался внутри, всё ещё снаружи |

**Второго фактора нет, и это осознанно.** Он тут был, и его убрали после
первой живой установки: почтового сервера нет, поэтому коды подтверждения
приходилось доставать из файла внутри контейнера, а на регистрацию устройства
уходило шесть шагов и две консоли. Защита, которой невозможно пользоваться,
не защищает — ею просто перестают пользоваться.

Вернуть его несложно, если появится почтовый сервер: в
`authelia/configuration.yml` заменить `one_factor` на `two_factor` и настроить
`notifier.smtp`.

Забытый пароль гейта не запирает вас навсегда: доступ по SSH к машине есть
всегда, а пользователь правится в `authelia/users.yml`.

## Приём метрик: почему он не за гейтом

Нода не умеет проходить интерактивный вход. Значит у неё свой маршрут со своей
проверкой — и он **узкий намеренно**:

```
@push {
    path /api/v1/import*
    method POST
    header Authorization "Bearer {$SHAPE_PUSH_TOKEN}"
}
```

Совпасть должны все три условия. Путь ограничен потому, что у
VictoriaMetrics по соседству живёт удаление рядов
(`/api/v1/admin/tsdb/delete_series`): открыв сюда всё хранилище, мы отдали бы
владельцу токена возможность стереть историю. А токен лежит на 28 нодах и рано
или поздно утечёт.

**Что даёт украденный токен:** писать мусорные метрики. Читать — нет, удалять —
нет, трогать ноды — нет.

Токен один на все ноды. Отдельный на каждую строже, но это 28 токенов в
управлении; при 28 нодах размен в пользу простоты, при сотне я бы думал иначе.

## Настройка ноды

```bash
shaperctl metrics set --url https://push.<домен>/api/v1/import/prometheus \
                      --token ТОКЕН_ИЗ_.env
shaperctl metrics push        # проверить прямо сейчас
systemctl enable --now shape-push.timer
```

Подробности — в [../grafana/README.md](../grafana/README.md).

## Что внутри

| Контейнер | Версия | Порты наружу |
| --- | --- | --- |
| caddy | 2.8-alpine | **80, 443** |
| victoriametrics | v1.102.0 | нет |
| grafana | 11.2.0 | нет |
| authelia | 4.38 | нет |

Наружу смотрит ровно один контейнер. Остальные доступны только внутри сети
docker: если Grafana однажды окажется доступна напрямую, гейт перестанет
что-либо значить, а заметить это можно будет только по последствиям.

Версии прибиты намеренно. Конфигурация Authelia менялась между 4.37 и 4.38
несовместимо, и `latest` однажды утром просто не поднимется.

## Сколько это стоит

Хранение: 28 нод × ~25 рядов × замер в минуту. VictoriaMetrics сжимает такое
до **десятков мегабайт в месяц**. Срок хранения — год, задан в
`docker-compose.yml`.

Трафик: около 4 КБ в минуту с ноды, то есть примерно **170 МБ в месяц** со всех
двадцати восьми.

## Обслуживание

```bash
cd shape/monitor
docker compose logs -f caddy          # кто приходил и с чем
docker compose logs -f authelia       # попытки входа
docker compose pull && docker compose up -d   # обновление образов
```

Резервная копия — это два тома и два файла:

```bash
docker run --rm -v shape-monitor_vm-data:/d -v "$PWD":/b alpine \
    tar czf /b/vm-data.tgz -C /d .
cp .env authelia/users.yml /куда-нибудь/надёжно/
```

`.env` и `authelia/users.yml` в репозиторий не попадают — см. `.gitignore`
рядом. Копию храните отдельно: в них токен, пароли и хеш вашего пароля.
