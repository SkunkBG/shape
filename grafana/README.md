# Мониторинг Shape

<p align="center">
  <b>Русский</b> · <a href="README.en.md">English</a>
</p>

Ноды отдают метрики в формате Prometheus. Дашборд рассчитан на парк из
десятков нод: везде разбивка по `node`, поэтому одна панель показывает все
серверы сразу.

Настраивается всё в меню: **Сервис → 📈 Мониторинг**. Там же показан готовый
кусок `scrape_configs` под выбранный способ.

## Путь первый: файл для node_exporter

Подходит, если node_exporter на ноде уже стоит. Никаких открытых портов и
токенов: Shape раз в минуту пишет `shape.prom` в каталог textfile, экспортёр
сам его подхватывает.

В меню — **Писать файл для node_exporter**. Мастер сам ищет каталог, ставит
таймер и проверяет, что файл появился. Вручную то же самое:

```bash
shaperctl.py metrics --out /var/lib/node_exporter/textfile_collector/shape.prom
```

В Prometheus добавлять нечего — метрики Shape приедут вместе с метриками
node_exporter, в том же job.

Проверить:

```bash
shaperctl.py metrics | head
curl -s localhost:9100/metrics | grep shape_
```

## Путь второй: нода отправляет сама

Единственный путь, который работает из стран, где блокируют VPN, и из-за NAT:
нода раз в минуту сама отправляет метрики на сервер мониторинга обычным
исходящим HTTPS. **Ни одного входящего порта на ноде не открывается.**

```bash
shaperctl metrics set --url https://metrics.example.com/api/v1/import/prometheus \
                      --token ТОКЕН_ЗАПИСИ
systemctl enable --now shape-push.timer
```

Проверить прямо сейчас:

```bash
shaperctl metrics push
shaperctl metrics show
```

Адрес задаётся **целиком, вместе с путём**: Shape не знает и не должен знать,
какое хранилище стоит на той стороне. Тело запроса — тот же текст, что уходит в
файл для node_exporter; каждый ряд уже несёт метку `node`, поэтому получателю
не нужно ничего дописывать, и неважно, сколько нод пишет в одно место.

Токен уходит заголовком `Authorization: Bearer`. Лежит он в
`/etc/shaper/config.json`, а не в systemd-юните: секрет в юните виден всякому,
кто может читать `/etc/systemd`.

**Простой `http` наружу запрещён** — по нему токен ушёл бы открытым текстом.
К `127.0.0.1` и в приватные сети можно.

Если до сервера иначе не достучаться, есть `--proxy socks5://…` — тот же
механизм, что у Telegram.

Таймер стреляет раз в минуту с разбросом в 15 секунд: 28 нод, обновившихся
разом, иначе приходили бы в одну и ту же секунду.

## Путь третий: через API

Подходит, если API уже установлен и мониторинг до него дотягивается.

```bash
sudo bash install.sh --with-api
TOKEN=$(sudo /opt/shaper/api/server.py --print-tokens | awk '/read/{print $2}')
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8765/metrics | head
```

Чтобы Prometheus мог дотянуться до ноды, API должен слушать не только
`127.0.0.1`. Правильный способ — приватная сеть, а не публичный адрес:
меню → **Сервис → 🔗 API ноды**, задать адрес интерфейса WireGuard и
разрешённые сети.

```
Адрес прослушивания : 10.100.0.7
Разрешённые адреса  : 10.100.0.2/32
```

Токен чтения передаётся заголовком — Prometheus это умеет из коробки:

```yaml
scrape_configs:
  - job_name: shape
    metrics_path: /metrics
    scrape_interval: 30s
    authorization:
      type: Bearer
      credentials: "ТОКЕН_ЧТЕНИЯ"
    static_configs:
      - targets:
          - 10.100.0.7:8765
          - 10.100.0.8:8765
          - 10.100.0.9:8765
```

Токен на всех нодах свой. Если удобнее один общий — задайте его вручную
в `/etc/shaper/api.json` при раскатке; менять токены потом можно без простоя,
прежняя пара принимается ещё сутки.

Можно и вовсе открыть метрики без токена — но только когда API уже спрятан
в приватную сеть. Тогда в `api.json` ставится `"metrics_public": true`, а в
`scrape_configs` секция `authorization` не нужна.

## В Grafana

**Dashboards → New → Import → Upload JSON file** и выбрать
`shape-dashboard.json`. При импорте Grafana спросит источник данных —
укажите свой Prometheus.

Что внутри:

| Ряд | Что показывает |
|---|---|
| Парк нод | сколько нод отвечает, где не загружен движок, где молчит сторож, общий канал, сколько адресов ограничено |
| Канал | скачивание и отдача по нодам с накоплением, итог закрытых суток, производная от счётчиков |
| Адреса и ограничения | динамика ограничений, активные адреса, персональные скорости, события за сутки |
| Состояние нод | таблица: версия Shape, аптайм, лимит, интерфейс, загружен ли движок |

Отметки на графиках появляются при перезапуске движка — по ним видно,
связан ли провал трафика с обновлением или с чем-то ещё.

## Метрики

| Метрика | Тип | Смысл |
|---|---|---|
| `shape_up` | gauge | метрики собраны |
| `shape_metrics_complete` | gauge | 0 — карты BPF прочитать не удалось, цифры неполные |
| `shape_info{node,version,api_version,interface}` | gauge | постоянные сведения о ноде |
| `shape_engine_loaded` | gauge | карты eBPF закреплены |
| `shape_watchdog_active` | gauge | сторож запущен |
| `shape_uptime_seconds` | gauge | сколько работает движок |
| `shape_speed_limit_mbps` | gauge | общий лимит на адрес |
| `shape_guard_enabled` | gauge | включено ли автоограничение |
| `shape_traffic_bytes_total{direction}` | counter | байты с запуска движка |
| `shape_channel_mbps{direction}` | gauge | текущая нагрузка канала |
| `shape_ips_known` / `_active` / `_limited` / `_personal` / `_whitelisted` | gauge | адреса в разных состояниях |
| `shape_owners_known` | gauge | для скольких адресов известен владелец |
| `shape_events_24h{type}` | gauge | события за сутки по типам |
| `shape_last_day_bytes{direction}` | gauge | трафик последних закрытых суток |

Если метрики идут через API, к ним добавляются `shape_api_up` и
`shape_api_uptime_seconds` — их нет в файловом пути, потому что без API их
не существует.

`shape_traffic_bytes_total` обнуляется при перезапуске движка — это обычное
поведение счётчика, `rate()` в Prometheus такие сбросы обрабатывает сам.

## Сколько это стоит ноде

Один сбор метрик — это дамп двух карт BPF и разбор журнала событий за сутки.
В API результаты кэшируются: дамп на 2 секунды, разбор событий на 30, так что
даже опрос раз в секунду не превратится в нагрузку. Таймер из файлового пути
работает раз в минуту, и на слабой ноде это десятки миллисекунд процессорного
времени в минуту.

Скорость канала считается по разнице с прошлым замером. Замер лежит в
`/var/lib/shape/metrics.state` — три числа. Поэтому она работает и при разовом
запуске из CLI, и при любом сочетании источников: неважно, кто мерил в прошлый
раз, таймер или API.
